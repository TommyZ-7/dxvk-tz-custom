## Scope

A0 only establishes the fork and a repeatable, bit-reproducible Windows x64 MinGW
cross-build of `d3d11.dll` and `dxgi.dll`. It does not contain, enable, or
test any VRS code. The reference VRS patch is not applied on this branch.

Non-goals: VRS implementation, 32-bit builds, D3D8/D3D9/D3D10 artifacts,
release publishing, and forward-porting to current upstream `master`.

## Build

Prerequisite: all submodules must be initialized at the revisions recorded
by the pin.

```sh
git submodule update --init --recursive
```

Exact commands used for the clean A0 build:

```sh
export MINGW_PREFIX=/home/tommyz7/work-saeki/toolchains/llvm-mingw-20261104-ucrt-ubuntu-22.04-x86_64
export PATH="$MINGW_PREFIX/bin:/home/tommyz7/work-saeki/toolchains/meson-venv/bin:$PATH"
cd /home/tommyz7/work-saeki/wt/dxvk-a0

rm -rf build.w64
meson setup build.w64 \
  --cross-file build-win64-llvm-mingw.txt \
  --buildtype release \
  --wrap-mode=nodownload \
  -Denable_d3d8=false \
  -Denable_d3d9=false \
  -Denable_d3d10=false

ninja -C build.w64 src/d3d11/d3d11.dll src/dxgi/dxgi.dll
```

The same build is wrapped by
[`scripts/build-win64.sh`](../../../scripts/build-win64.sh):

```sh
MINGW_PREFIX=/path/to/llvm-mingw-20261104-ucrt-ubuntu-22.04-x86_64 \
MESON=/path/to/meson \
  ./scripts/build-win64.sh
```

The Meson options match the reference build configuration:
`-Dbuildtype=release -Denable_d3d8=false -Denable_d3d9=false -Denable_d3d10=false`.
`--wrap-mode=nodownload` makes the build use the checked-out submodules
instead of fetching anything.

Build result: exit code `0`, 257 ninja steps, both DLLs linked.

The build is bit-reproducible: `scripts/build-win64.sh` sets
`SOURCE_DATE_EPOCH` from the commit timestamp, the cross file passes
`-Wl,--no-insert-timestamp`, and an existing build directory is wiped
before setup. `scripts/check-repro.sh` builds twice and compares the DLL
hashes; CI runs the same check.

## Blockers and non-blocking notes

No A0 blockers. The build succeeds with the pinned toolchain.

- The A0 pin predates the upstream `--disable-long-section-names` EA
  workaround; that workaround would require a separate forward-port.
- Clang emits upstream-code warnings such as
  `-Wdelete-non-abstract-non-virtual-dtor` while compiling D3D11 state
  objects. The project does not use `-Werror`; the build completes.
- D3D8/D3D9/D3D10 are disabled, matching the reference configuration.
  Only `d3d11.dll` and `dxgi.dll` are built and verified.
- No system Meson or MinGW was installed; no sudo or system package
  installation was attempted.

## A1 handoff

A1 starts from this pin and branch, not from current upstream master.

- Adapt the reference's fixed-centre VRS path, driven by
  `DXVK_GAZE_FAKE=fixed`.
- Remove the shared-memory gaze dependency entirely: no
  `/dev/shm/wivrn_gaze`, no WiVRn patch, no WiVRn GPL code.
- Keep the A0 cross file and Meson options unless a change is documented.
- Forward-porting the fork to current upstream master is a separate later
  change.

Settings contract items to reflect in A1 (not implemented in A0):

- `scene_format` default `"rgba16f"` (the reference's `fmt=97` scene pass).
- `flip_y` default `true` (the reference's `FLIP_Y=1`).
- RADV GFX11 effective fragment shading rate set:
  1x1, 1x2, 2x1, 2x2.
- MSAA `sampleCounts` of interest: 1, 2, 4.
